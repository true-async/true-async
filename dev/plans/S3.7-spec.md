# S3.7 spec: waiting for a coroutine

The PHP-visible behaviour of S3.7 (`dev/PLAN.md`): `Async\await()` on a coroutine, the garbage
collector waiting for its run, and `Coroutine::getAwaitingInfo()`. Sources: `dev/plans/S3.md`
section 4 (the wait model), TrueAsync (true-async/php-async at `tests/lists/REFERENCE`), the RFC
core's `Zend/zend_async_API.h` and `Zend/zend_gc.c`, the core's reference scheduler
`ext/test_scheduler/test_scheduler.c`.

## Running order (context, already built in S3.5 and S3.6)

The script's top level runs in the main coroutine. `Async\spawn($callable, ...$args)` queues a new
coroutine and returns its `Async\Coroutine` object; queued coroutines run one at a time in FIFO
order, each until it ends, yields or waits. `Async\suspend()` yields: the current coroutine goes to
the back of the queue. When the script's top level ends, the queued coroutines run to their end
before the request ends. An exception thrown out of a spawned coroutine that nothing awaits and no
variable holds ends the request as `Fatal error: Uncaught ...` after the queue drains.

## Items

1. `await($coroutine)` returns the value the coroutine's callable returned, once the coroutine has
   finished. Source: S3.md 4.8; TrueAsync `async.c:296-380`.
2. A coroutine whose callable returns nothing (or `null`) gives `null`. Source: TrueAsync
   `async.c:373-375`.
3. When the coroutine ended with an exception, `await()` throws that exception object: the same
   object as `$coroutine->getException()`, and the same object again at every later `await()` of the
   coroutine. Source: TrueAsync `coroutine_replay` (`coroutine.c:1040-1068`); D33 ("replays its
   exception every time").
4. An exception that an `await()` delivered (item 3) does not also end the request as uncaught,
   whether the `await()` caught it before or after the coroutine finished. Source: TrueAsync marks
   the outcome caught at `await()` (`async.c:318-320`).
5. `await()` of a coroutine that has already finished returns (or throws) at once: no other queued
   coroutine runs before it returns. Source: S3.md 4.1, phase 1 (completion is checked before any
   wait).
6. `await()` of a coroutine that has not finished parks the caller: other queued coroutines run, the
   awaited one included, and the caller continues after the awaited coroutine has finished. This
   holds in the main coroutine and in a spawned one. Source: S3.md 4.1, 4.2.
7. Several coroutines (main included) may await the same coroutine at once: each one continues
   after it finishes and gets its result (or its exception, item 3). The order in which the waiters
   continue is not specified. Source: S3.md 4.8 (one record per waiter in the target's callbacks).
8. Chains work: when A awaits B and B awaits C, C's result reaches B, and B's return value reaches
   A. Source: items 1 and 6.
9. A coroutine that awaits itself (`await(Async\current_coroutine())`), in main or in a spawned
   coroutine, gets an `Error` with the message `Cannot await a coroutine from within itself` and
   goes on running. Source: S3.md 4.1 phase 0; the message is test_scheduler.c's (`ts_await`).
10. `await()` takes exactly one argument of type `Async\Completable` (in S3 only `Async\Coroutine`
    implements it): another object or a scalar gives a `TypeError`, no argument an
    `ArgumentCountError`. Source: the stub `src/true_async.stub.php`.
11. While a coroutine is parked in `await($target)`, `isSuspended()` and `isRunning()` of the waiter
    are `true` and `isCompleted()` is `false`; after the target finished and the waiter returned,
    the waiter is `isRunning()` while it runs on. Source: S3.md section 2 (the state formulas).
12. `getAwaitingInfo()` always returns an array. For a coroutine parked in `await($target)` it is a
    list with one string, `"await: coroutine #" . $target->getId()`; for a coroutine that is not
    awaiting (never started, running, yielded with `suspend()`, finished) it is an empty array.
    Source: S3.md 4.7; the wording is test_scheduler.c's (`ts_await_awaiting_info`).
13. `gc_collect_cycles()`, called in main or in a coroutine, returns only after the collection has
    run, including the destructors (`__destruct`) of the collected objects, even when a destructor
    suspends (`Async\suspend()`); it returns the number of collected cycles' objects as plain PHP
    does (two objects in one cycle: `2`). Source: the RFC core collects in a coroutine and the
    caller awaits it (`zend_gc.c:2245-2293`).
14. A coroutine that waits in `await()` keeps the awaited coroutine alive: `await(spawn(...))`, with
    no variable holding the coroutine, still returns its result. Source: S3.md 4, invariant F (the
    call argument holds the target).

## Errors and edge cases

- An exception thrown by the awaiting coroutine's own code after `await()` returned is its own, as
  without `await()`.
- `await()` of a coroutine that finished by an exception thrown in a nested function call: item 3.

## Test files

- Format: run-tests `.phpt` (`--TEST--`, `--FILE--`, `--EXPECT--` or `--EXPECTF--`); the runner
  loads the extension with `true_async.enable=1`, nothing else is needed in the file.
- Imports: `use function Async\spawn; use function Async\await; use function Async\suspend; use
  function Async\current_coroutine;`.
- Paths: `tests/wait/NNN-<what>.phpt`, three-digit numbers from `001`.

Run: `env TEST_PHP_JUNIT={junit} python3 tools/test.py --lane pocs-dbg --jobs 4`
